## Technical contribution outline for a developer audience

Working title: **Keeping a static tools site interactive without rebuilding its HTML on first load**

1. Show the problem: a static page already contains its heading and instructions, while startup JavaScript imports editorial data and replaces the same content.
2. Explain the public browser catalogue, deferred route templates, and preserving the initial DOM.
3. Show the reproducible static-import budget check in `scripts/client-assets.mjs` and the relevant tests.
4. Report the measured source graph: 21 modules / 364,970 bytes before; 8 modules / approximately 93 KB after. These are uncompressed code bytes, not user latency measurements or a new Lighthouse score.
5. Explain the one content-addressed stylesheet and cache policy, plus the limitations of synthetic benchmarks.
6. Include actual code and caveats; link the source repository where readers need it. A contextual product link can identify the implementation, without repeated keyword anchors.

This is an outline, not a published guest article. A complete original technical post should be reviewed for the destination's audience before posting.
